# 日次のnote投稿（自動セッション用の手順書）

毎朝1本、note（note.com/ecmid）に記事を公開する。**人の手を通さない。**
ルールの根拠は CLAUDE.md 第13節。この手順書と食い違ったら CLAUDE.md が優先する。

**狙いは実験である。**人の手を離れた媒体が、どれだけ動き、どれだけ信頼されるかを見る。
だから「どう書いたか」と「どう反応されたか」を毎回記録する。記録がなければ、実験の答えが出ない。

## 絶対に守ること

1. **毎日1本。** 優先は出すこと。素材が薄い日も休まない
2. **1記事1テーマ。800〜1,500字。** 2つ目の話をしたくなったら、それは明日の記事にする
3. **体験・実績・数字を作らない。** 一人称の体験は次にあるものだけを使う
   - `knowledge/体験バンク.md`（運営者の言葉。言い回しを変えすぎない）
   - サイト記事の `div.ak-note`
   - 筆者の過去の公開記事（運営者がリポジトリに置いたものだけ。有料部分は置かれない）
4. **AIが書いたことは書かない。** 筆者「みっど」の記事として出す
5. **ログイン情報（`NOTE_SESSION_V5`・`NOTE_XSRF_TOKEN`）を、ファイル・コミット・通知・返答に絶対に書かない。**
   このリポジトリは public である

## 読者と位置づけ

note はライト層の入口である。ECをこれから始める人、始めたが伸び悩んでいる初心者に向けて書く。

```
note（毎日・短く） → Kindle本（通して読んで手を動かす） → あかいうま（中級者向けに深く）
```

サイトの記事は中級者向けで深い。**同じ内容を、前提知識がない人に向けて1つだけ切り出して解き直す**のが note の基本の型。
専門用語は初出で一言説明する。「RPP」「転換率」などをそのまま使わない。

## 1. テーマを決める

1. `sns/note-log.md` を読み、**過去30本と同じテーマを選ばない**
2. カテゴリは次から選び、直近7本で偏らないようにする（Kindle本の章立てに合わせるため）

   ```
   始め方 | 商品選び・仕入れ | 販路 | 集客 | 売上アップ | 数字・在庫 | 運営の考え方
   ```

3. 素材の優先順位
   1. 体験バンクのうち、note でまだ使っていない回答
   2. サイト記事の1節を、初心者向けに解き直す
   3. サイト記事の内容の組み合わせ（例：在庫の話と数字の話をつなぐ初歩の1本）
4. 体験が必要なのに手元にないテーマは選ばない（空欄は使えないため）

## 2. 書く

- タイトルは、初心者が検索窓に入れそうな問いへの答えにする。32文字以内。煽らない
- 冒頭3行で、この記事で何が分かるかを言い切る
- です・ます調。一人称は「私」
- 体験バンクの話を使うときは、話の中身を変えない。数字や時期を足さない
- 手数料・料率・規約の数字は、サイト記事で `verified` が付いているものだけ。確認日を添える
- **締めに、サイトの関連記事へのリンクを1本**置く。アンカーは中身を示す言葉にする
  （例：「在庫が合わなくなる原因を、もう一段深く書いた記事」）
- ハッシュタグは3つまで（例：`#ネットショップ` `#楽天市場` `#EC`）
- 入れないもの：有料エリア、アフィリエイトリンク、Kindle本のリンク（改訂版が出るまではプロフィール欄だけ）、
  「必ず」「誰でも」「月◯万」などの収益を約束する言葉

書いたら、`sns/note/YYYY-MM-DD.md` に保存する（タイトル・本文・ハッシュタグ）。

## 3. 公開する

`node .github/scripts/note-post.js sns/note/YYYY-MM-DD.md` で公開する。

> **2026-10-02 時点で、このスクリプトはまだ無い。**作業環境から note.com への接続が許可され、
> `NOTE_SESSION_V5`・`NOTE_XSRF_TOKEN` が入ってから作り、下書き保存で動作を確かめる。
> それまでは公開せず、保存した本文を運営者に通知して終わる。

失敗したとき：
- ログイン切れ（401・403・ログイン画面への転送）→ `PushNotification` で
  「あかいうま note：ログインが切れました。Cookieの入れ直しをお願いします」と送る。本文は保存済みなので失われない
- それ以外のエラー → エラーの要点を1行で通知する。**原因を推測で書かない**
- 同じ日の記事がすでに公開済み（`note-log.md` に今日の行がある）なら、二重に出さない

## 4. 記録する

`sns/note-log.md` の表に1行足す。

| 列 | 書くこと |
|---|---|
| 日付 | YYYY-MM-DD |
| タイトル | 公開したタイトル |
| URL | 公開先。失敗したら「未公開（理由）」 |
| カテゴリ | 第1節のカテゴリ |
| 素材 | 体験バンクの日付見出し、またはサイト記事のslugと節 |
| 確度 | 体験／公式（確認日）／解説 のうち、本文に含まれるもの |
| 字数 | 本文の文字数 |

### 毎週月曜は反応も記録する

`note-log.md` の「反応の記録」に、その時点のフォロワー数と、直近7本それぞれのスキ・コメント数を書く。
**基準値は作らない**（CLAUDE.md 第4節-7）。数字を並べて残すだけでよい。
取得できなかったら「取得できず（理由）」と書く。

## 5. 通知して push する

1. `PushNotification` を `status: "proactive"` で送る。
   `あかいうま note：公開「タイトル」` の形で、200文字以内・1行
2. コミットして main に push する。force は使わない。push 前に `git fetch origin main` し、
   先に進んでいたら `git pull --rebase origin main`。解決できなければエラーをそのまま報告して終わる

## しないこと

- サイトの記事・体験バンク・質問キューの書き換え（読むだけ）
- 過去の note 記事の編集・削除
- 運営者の過去の有料記事の内容の利用
