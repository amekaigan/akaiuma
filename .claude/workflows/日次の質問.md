# 日次の質問（自動セッション用の手順書）

1日1問だけ、運営者に実体験を聞く。答えを `knowledge/体験バンク.md` に貯める。

**狙いは、記事を書く前に素材を貯めておくこと。**
書くときに質問すると、運営者が動けない週は記事も止まる。先に貯めておけば止まらない。

## 絶対に守ること

1. **1回に1問だけ。** 2つ以上を並べると答えるのが重くなり、返事が来なくなる
2. **答えを要約しない。** 運営者の言葉のまま `体験バンク.md` に残す。言い回しにその人の判断が出る
3. **答えを勝手に記事に入れない。** 記事化はディレクターの判断を経る
4. **未回答の問いは、最大3回まで再送する。** 送るたびに何回目かを明示する（次節）

## 再送のルール

当初は「返事がなくても催促せず、翌日は別の問いを送る」としていた。
これは「見たけれど答えなかった」場合を想定したルールだった。

実際には、**通知が他のやり取りに埋もれて気づかれない**ことがある。
見ていない問いを捨てると、キューだけが減っていく。そのため再送する。

- 未回答なら、**同じ問いを最大3回まで**送る
- 2回目以降は、本文の冒頭に `（2回目）` `（3回目）` と明示する。
  何回目かが分かれば、運営者が次から気をつけられる
- 3回送っても未回答なら `[x]` にし、`回答なし（3回送信）` と記録して次の問いへ進む
- 催促の言葉は添えない。回数を示すだけでよい

### 送信回数の記録

`knowledge/質問キュー.md` の行末に `｜送信:N（YYYY-MM-DD）` を付けて管理する。
印がない行は、まだ一度も送っていない問い。

```
- [ ] 自社出荷を残している商品はありますか｜送信:2（2026-09-21）
```

## 手順

0. **先に `knowledge/inbox.md` を見る。** 運営者はiOSショートカットから回答することがあり、
   その場合セッションには届かず inbox に入る。前回の問いへの回答が入っていたら、
   先に処理すること（下の「inboxに回答が入っていた場合」を参照）。
   これを飛ばすと、答えたはずの問いをもう一度送ることになる
1. `knowledge/質問キュー.md` を開く
   - `[ ]` の行のうち、**送信済みで未回答のもの（送信:1〜2）があれば、それを再送する**
   - なければ、`[ ]` の行の**先頭から1つ**選ぶ
2. その問いを運営者に送る。前置きは1〜2行まで。なぜ聞くのか（どの記事に使うか）を添える。
   再送のときは冒頭に `（2回目）` `（3回目）` を付ける
3. `knowledge/今日の質問.md` を、いま送った問いの内容で上書きする（後述）
4. 答えが返ったら
   - `knowledge/体験バンク.md` に、日付・テーマ・問い・答え・使えそうな記事を追記する
   - `質問キュー.md` の該当行を `[x]` に更新する
   - コミットして push する（ブランチは main で構わない。記事本文は変更しないため）
5. 答えが「分からない」「覚えていない」だった場合
   - 埋めようとしない。`質問キュー.md` の行に「回答なし」と記録して `[x]` にする
   - 同じ問いを翌日また送らない（再送のルールの対象外。見たうえで答えられなかったため）

## 今日の質問.md について

通知を見逃しても後から読めるように、送った問いを `knowledge/今日の質問.md` に残す。
毎回上書きでよい（履歴は質問キューと体験バンクに残るため）。

この形式で書く。

```
# 今日の質問

（問いの本文）

- 送った日：YYYY-MM-DD
- 送信回数：N回目
- なぜ聞くか：（どの記事のどこに使うか）

## 答え方

- 通知に返信する（いちばん確実。その場で体験バンクに記録される）
- iOSショートカットで送る（翌日のルーティンが拾う。1行目に問いを書くこと）
```

## inboxに回答が入っていた場合

1. `knowledge/体験バンク.md` に転記する。**要約しない。運営者の言葉のまま**
2. `質問キュー.md` の該当行を `[x]` にする
3. inbox の該当箇所の末尾に `→ 体験バンク.md に転記済み（YYYY-MM-DD）` と書き添える。
   **原文は消さない。**二重に処理しないための印であって、記録を消すためではない
4. そのうえで、当日の1問を送る

inbox には思いつきのメモも混ざる。**問いへの回答なのか、ただのメモなのかを見分けること。**
判断がつかないものは転記せず、inbox に置いたままにする。

## キューが尽きたら

`knowledge/記事の企画リスト.md` の未着手の企画を読み、そこから新しい問いを5つ作って
`質問キュー.md` に追記する。問いは、運営者がその場で答えられる具体性にすること。
